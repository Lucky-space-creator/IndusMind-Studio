## 2. P0 演示闭环可达性验证（核心链路）

```
[管理端] 设备配置(dev_*) → 知识库+文档上传+分段(kb_*) → 索引构建(kb_index_task→/rag/index→pgvector)
       → 文档关联抽取(kb_graph_*→/graph/extract→Neo4j) → 数据导入/模拟(data_dataset/record)
       → 清洗(data_cleaned) → 异常提取(data_anomaly) → Agent/流程配置(agent_*) → 发布(pub_*)
[用户端] 看板(wo_dashboard_metric) → 问答(chat_session/message→/chat)
       → 协同诊断(agent_run/step→/diagnosis/run) → 诊断记录(diagnosis_record)
       → 工单(wo_work_order/_part) → 导出下载(file_url)
```

**结论**：闭环链路在表/接口/模块三层均可达；但有 4 处断点（问题 A2/A3/A4/A6），修复后完整。

## 3. 发现的问题与处置

### A. P0 级（必须在开发前修复）

**A1【文档间矛盾】配置员数据管理权限不一致**
- 现象：需求 §1.4 配置员关键权限="知识库、GraphRAG、Agent/流程、发布监控"（**无数据**）；但前端布局 §8.4 矩阵给配置员"管理端·数据管理 ✅"；V2__init_data.sql 据后者给配置员配了 data:*（25–31）。
- 裁定：需求文档为**唯一权威**（其自我声明"权限矩阵以 M01 为准，其他模块不得自定义"）。
- 处置：① V2__init_data.sql 配置员**移除 data:\***（25–31）；② 前端布局 §8.4"配置员×数据管理"改 `–`；③ 补配置员 device 只读（1,3,5,7,9,11，对齐 §8.4"设备配置只读"，便于绑定知识库分类时查看设备类型，只读无风险）。
- 演示影响：数据准备（导入/模拟/清洗）由管理员执行，链路不变。

**A2【契约缺漏】文档生命周期变更缺少同步接口**
- 现象：文档停用/删除/知识库删除后，pgvector 向量与 Neo4j 图无法同步（契约仅有 index/reindex/search/extract/query）。
- 处置：AI 契约新增 3 个接口——
  - `POST /rag/document-status`：批量更新 doc_status（文档启停，停用片段不参与检索，REQ-M03-02）
  - `POST /rag/delete`：按 kb_id/doc_id 删除向量（文档/知识库删除）
  - `POST /graph/sync`：按 kb_id 全量重建图（人工增删改边后/抽取重跑）
- 同步修改：Python服务详细设计 §3、Java后端详细设计 §9（RagClient/DocGraphClient）、总纲 §6.2。

**A3【职责矛盾】分段逻辑归属两文档冲突**
- 现象：Python 服务设计 §4 RAG 流水线含"分段(长度/重叠/按章节)"；但 kb_segment（片段）是 MySQL 权威表且片段校对（REQ-M03-06）在 Java 管理端——分段必须在 Java 侧完成，否则片段校对与索引内容会漂移。
- 裁定：**分段归 Java**（hwc-knowledge：文档解析→分段→落 kb_segment→携片段文本调 /rag/index）；Python 只做 Embedding+索引+检索。
- 处置：修改 Python 服务详细设计 §4 流水线描述；Java 侧引入 Apache Tika（pdf/docx 文本提取，新增依赖，本报告评审通过）。

**A4【权限点缺漏】用户端"知识检索"页无权限点**
- 现象：前端 §6.9 用户端知识检索（只读手册检索）页面存在，但 58 个权限点无对应项，接口无法鉴权。
- 处置：新增权限点 `59 knowledge:search:read`（user 端），授予 ENGINEER、REVIEWER（与问答角色一致）。

**A5【DDL bug】`agent_run.device_id NOT NULL` 误伤单 Agent 问答**
- 现象：run_type=single（/chat 触发）为通用问答，无设备上下文，NOT NULL 会插入失败。
- 处置：改为 `NULL DEFAULT NULL`；diagnosis 类型应用层必填校验。

**A6【设计缺漏】M08 发布服务的调用入口未定义**
- 现象：pub_call_log 有表无写入方；发布的服务无法被调用演示。
- 处置：Java 新增开放 API `POST /api/open/v1/{serviceCode}/invoke`——鉴权 Bearer（access_key:secret 的 Base64，HMAC 签名列 P1）；内部触发协同流程→agent_run→返回结论；写 pub_call_log。修改 Java后端详细设计 §6/§9。

**A7【设计缺漏】健康看板快照生成时机未定义**
- 现象：wo_dashboard_metric 有表无生产方。
- 处置：① 数据集异常提取完成时发领域事件→workorder 监听重算该设备快照（评分按 wo_score_rule：device>device_type>global 取规则）；② 管理端/用户端提供手动刷新接口。写入需求分析决策（不改需求文档，实现遵循）。

**A8【设计缺漏】工单导出文件格式未定**
- 现象：REQ-M09-04"可打印/存档文档"未定格式。
- 处置：HTML 模板渲染 + openhtmltopdf 导出 PDF（Java 侧，新增依赖，评审通过），存 MinIO 回填 file_url；工单状态流转 generated→（导出时）confirmed/exported。

### B. P1 级（记录，不阻塞 P0）

**B1** `agent_flow_node` 无 (flow_id, node_order) 唯一约束——应用层校验排序唯一。
**B2** 数据范围（sys_role_data_scope）与 Agent 数据范围约束（REQ-M01-04）为 P1，P0 全量可见。
**B3** 故障溯源图（REQ-M09-03）P1；P0 用诊断详情的引用列表+抽屉原文替代。
**B4** LLM/Embedding 离线风险：演示依赖模型可用性。处置：core/ 支持 provider 可配置（dashscope/ollama/openai 兼容），演示优先 ollama（qwen2.5 + bge-m3 本地）；pgvector 维度随嵌入模型调整（DDL 已注明）；**部署清单必须含模型预下载**。

### C. 触发条件 DSL 定义（补契约，防两方理解漂移）

`agent_flow_node.trigger_condition` 表达式由 **Python 编排器**解释，语法：
```
expr    := term (('&&' | '||') term)*
term    := <agent_code>.<field> <op> <value>
op      := == | != | > | < | >= | <=
value   := 布尔 | 数字 | 单引号字符串 | 枚举字面量
```
- `<field>` 为该 Agent `output_format` 中的顶层字段（如 `monitor.deviceStatus`、`safety.checkResult`）。
- 预设流程示例：`monitor.deviceStatus != 'normal'`、`safety.checkResult == 'passed' && spare_cost.completed == true`。
- 未定义字段/解析失败 → 该节点跳过并记录 agent_step(status=skipped)，不中断流程。
