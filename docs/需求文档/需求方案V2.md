# 工业设备巡检与运维智能系统 — 需求方案

> 版本：V2.0
> 基线：`docs/需求文档/需求方案.md`（V1.0）
> 本文对 V1 进行整改，整改方向：①双端（用户端 + 管理端）②真实设备配置 ③RAG 知识库管理 ④GraphRAG 文档关联（LangGraph）⑤单 Agent 问答 ⑥多 Agent 协同（领域边界）。
> 自洽性校验见第 6 章。

---

## 1. 总体需求

### 1.1 项目定位

建设面向工业设备巡检与运维的**智能系统**，解决**告警难分析、维修知识难查找、诊断与工单脱节**三大问题。系统的核心是一条「知识沉淀 → 智能问答 → 多 Agent 协同诊断 → 工单交付」的主线：

- 以 **RAG** 管理知识库，负责「检索到具体片段」；
- 以 **GraphRAG（LangGraph）** 管理文档间关联，负责「片段之间的关系导航」；
- 以 **单 Agent** 提供通用智能问答；
- 以 **多 Agent** 提供分领域、有边界的协同诊断；
- 以**真实设备配置**为数据锚点，在无真实设备接入时用模拟数据完成端到端演示。

### 1.2 双端架构

系统分为两个独立入口，**共用同一套后端服务与数据底座**，仅前端形态与可用功能不同：

| 端 | 面向角色 | 定位 | 主要能力 |
|----|----------|------|----------|
| **用户端** | 维修工程师、生产管理人员、评审/体验用户 | 使用与查看 | 设备健康看板、智能问答、协同诊断发起与查看、故障溯源图、维修工单查看/下载 |
| **管理端** | 管理员、配置员 | 治理与配置 | 设备配置、知识库与 RAG、文档关联与 GraphRAG、设备数据管理、Agent 与流程编排、服务发布监控、账号权限、审计 |

设计原则：
- 用户端**不得**出现任何配置、治理、发布类入口；管理端**不承担**面向维修工程师的日常诊断操作（但可发起测试）。
- 两端对同一业务对象（设备、知识、诊断记录、工单）**读写权限严格区分**，详见 M01 与 M10。

### 1.3 核心能力总览（对应六项整改）

| 整改项 | 落地模块 | 说明 |
|--------|----------|------|
| 双端 | M01 / M10 | 用户端 + 管理端，共用后端，权限隔离 |
| 真实设备配置 | M02 | 设备类型/型号/厂商/监测指标/阈值/备件/停机损失的可维护配置 |
| RAG 知识库管理 | M03 | 文档上传→分段→向量化→索引→检索→重排的完整链路 |
| GraphRAG 文档关联 | M04 | 用 LangGraph 构建**可管理、可修改**的文档/片段关系图，**只做文档间关联** |
| 单 Agent 问答 | M06 | 通用智能问答，RAG + GraphRAG 双知识源，带引用 |
| 多 Agent 协同 | M07 | 分领域 Agent（监测/诊断/备件成本/安全/工单），明确边界与仲裁 |

### 1.4 用户角色与双端归属

| 角色 | 端 | 职责 | 关键权限 |
|------|----|------|----------|
| 管理员 | 管理端 | 资料与数据治理、账号权限、审计 | 设备配置、知识库、数据、账号、审计 |
| 配置员 | 管理端 | 配置 Agent 与流程、维护文档关联、发布服务 | 知识库、GraphRAG、Agent/流程、发布监控 |
| 维修工程师 | 用户端 | 发起/查看诊断、问答、核对依据、导出工单 | 问答、诊断、工单查看下载、溯源图 |
| 生产管理人员 | 用户端 | 查看设备状态与停机风险 | 看板、风险提示（只读诊断结论） |
| 评审/体验用户 | 双端（只读） | 通过样例验证完整流程 | 双端只读 + 演示路径 |

> 权限矩阵以 M01 为准，角色与端、模块的对应关系为**唯一权威定义**，其他模块引用之，不得自定义。

### 1.5 业务流程（端到端主线）

```
[管理端]
  设备配置(M02) → 知识库上传与RAG索引(M03) → 文档关联构建GraphRAG(M04)
              → 设备数据导入/模拟(M05) → 数据清洗与异常提取(M05)
              → Agent与协同流程配置(M07) → 测试与发布(M08)
[用户端]
  查看看板(M09) → 智能问答(M06) / 发起协同诊断(M07)
              → 查看诊断结论与引用溯源(M09) → 导出维修工单(M09)
```

### 1.7 优先级与交付范围

- **P0**：首期必须交付，构成可演示闭环。
- **P1**：增强功能，纳入当期则单独验收，未交付不影响 P0 验收。
- 首期必须提供**可运行的预设协同流程**；可视化拖拽编排为 P1（但 M07 的多 Agent 领域边界在 P0 即生效）。

### 1.8 术语表

| 术语 | 定义 |
|------|------|
| RAG | 检索增强生成；本文特指知识库片段级检索 |
| GraphRAG | 基于图的检索增强；本文特指**文档/片段间关联**的图结构，用 LangGraph 表达 |
| Agent | 单智能体，面向通用问答 |
| 多 Agent | 分领域智能体协同，用于复杂诊断 |
| 设备配置 | 真实设备的结构化定义（类型/型号/指标/阈值/备件） |
| 主数据 | 全系统唯一的权威基础数据（设备配置、备件、停机损失） |

## 2. 模块需求

### M01 账号与权限管理

**目标**：支撑双端与 5 类角色的访问控制，为所有模块提供统一的权限判定。

| 编号 | 名称 | 优先级 | 说明 |
|------|------|--------|------|
| REQ-M01-01 | 账号与登录 | P0 | 支持账号创建、登录、登出；密码加盐哈希存储；会话超时。 |
| REQ-M01-02 | 角色与端绑定 | P0 | 内置管理员/配置员/维修工程师/生产管理人员/评审用户五类角色，每类角色绑定可访问端（用户端/管理端/双端），并映射到 1.4 权限矩阵。 |
| REQ-M01-03 | 功能权限控制 | P0 | 按「角色×模块×操作（读/写/发布/删除）」鉴权，前后端双重校验（前端隐藏入口，后端强制拦截）。 |
| REQ-M01-04 | 数据范围权限 | P1 | 可配置角色可见的设备/知识库范围，Agent 访问数据时同样受此约束。 |
| REQ-M01-05 | 操作审计 | P0 | 记录登录、配置变更、发布、文档启停、工单导出等关键操作（操作人、时间、对象、前后值）。 |

**边界**：M01 只定义「谁能做什么」，不定义具体业务流程；其他模块的功能均须在 M01 权限矩阵内声明。

**验收要点**：越权访问被后端拒绝（返回明确中文提示）；用户端无法访问任何管理端接口。

---

### M02 设备配置管理（真实设备配置）

**目标**：建立**真实设备的结构化配置**，作为全系统主数据，替代 V1 中「纯模拟、无设备定义」的做法。

| 编号 | 名称 | 优先级 | 说明 |
|------|------|--------|------|
| REQ-M02-01 | 设备台账 | P0 | 维护设备实例：设备编号、名称、所属产线/位置、设备类型、厂商、型号、投运日期、状态。 |
| REQ-M02-02 | 设备类型与型号库 | P0 | 定义设备类型（如机床、电机、变压器）及其型号规格，供台账引用。 |
| REQ-M02-03 | 监测指标定义 | P0 | 为设备类型定义监测指标（温度、振动、电流、转速等），含单位、采样频率、**正常范围、预警阈值、故障阈值**。 |
| REQ-M02-04 | 告警规则配置 | P0 | 基于指标阈值定义告警等级（正常/预警/故障）与触发条件，供 M05 异常提取引用。 |
| REQ-M02-05 | 备件主数据 | P0 | 维护备件：名称、型号、适用设备/型号、库存、采购单价、安全库存。 |
| REQ-M02-06 | 停机损失标准 | P0 | 按设备/产线配置每小时停机损失标准。 |
| REQ-M02-07 | 配置导入导出 | P1 | 支持设备配置的批量导入/导出（表格模板）。 |
| REQ-M02-08 | 配置校验 | P0 | 保存时校验字段完整性、阈值区间合理性（预警阈值须包含于正常范围之外且严于故障阈值）。 |

**边界**：M02 是设备、指标、阈值、备件、停机损失的**唯一权威来源**；M05 用其阈值做清洗与异常判定，M07 的备件/成本 Agent 用其备件与停机损失，M09 用其台账。其他模块**不得**自行硬编码这些值。

**验收要点**：任一指标阈值的修改，能影响 M05 的异常提取结果与 M09 的看板状态。

---

### M03 知识库与 RAG 管理

**目标**：以 RAG 方式管理知识库，实现「检索到具体片段」的能力。

| 编号 | 名称 | 优先级 | 说明 |
|------|------|--------|------|
| REQ-M03-01 | 知识库管理 | P0 | 支持创建多个知识库，按设备类型、厂商、故障等级分类，展示文档数量与索引状态。 |
| REQ-M03-02 | 文档管理 | P0 | 支持维修手册、操作规程、历史维修记录的上传、预览、版本更新、启停、删除；**停用文档不参与检索**。 |
| REQ-M03-03 | 文档分段 | P0 | 支持配置分段长度、重叠字数或按章节切分；预览片段内容、数量、字数。 |
| REQ-M03-04 | 向量化与索引 | P0 | 将片段构建为可检索索引（向量 + 关键词混合），展示处理进度与就绪状态。 |
| REQ-M03-05 | 检索与重排 | P0 | 提供检索接口：相似度检索 + 关键词召回 + 重排，返回片段、来源章节页码与得分。 |
| REQ-M03-06 | 片段校对 | P1 | 片段文字编辑、关键词补充、片段分布展示；修改后可重建索引。 |
| REQ-M03-07 | 索引重建与版本 | P0 | 文档更新后支持重建索引；记录索引版本，检索可指定版本。 |

**边界**：M03 只回答「**哪些片段与查询相关**」，不回答「文档之间是什么关系」（那是 M04）。M03 不感知设备数据。

**验收要点**：停用文档后检索结果中不再出现其片段；索引构建有进度反馈。

---

### M04 文档关联与 GraphRAG（LangGraph）

**目标**：用 **LangGraph** 构建**可管理、可修改**的文档/片段关联图，**只做文档间关联**，为问答与诊断提供「关系导航」。

| 编号 | 名称 | 优先级 | 说明 |
|------|------|--------|------|
| REQ-M04-01 | 关联图构建 | P0 | 以文档/章节/片段为节点，以关系（引用、替代、补充、前置、同设备、同故障等）为边，构建关联图。 |
| REQ-M04-02 | 自动关系抽取 | P0 | 基于 LangGraph 流程自动抽取候选关系，生成**候选边**（标记来源=自动）；候选边**默认生效**，可由人工修正（见 REQ-M04-04）。 |
| REQ-M04-03 | 关系可视化 | P0 | 以图形式展示节点与边，支持按知识库、设备类型、关系类型过滤。 |
| REQ-M04-04 | 关系人工管理 | P0 | 支持**新增、修改、删除**边，修改节点标签/类型；区分「自动」与「人工」来源并留痕。 |
| REQ-M04-05 | 关系审核工作流 | P1 | 可开启「候选边须人工确认后才参与检索」的严格模式（默认关闭，即候选边默认生效）。 |
| REQ-M04-06 | 关联检索 | P0 | 给定片段/节点，按图扩展返回相关联节点（如「该手册的替代条款」「同故障的其他案例」）。 |
| REQ-M04-07 | 版本与回滚 | P1 | 关联图变更留版本，可回滚。 |

**边界（关键，防止与 RAG 混淆）**：
- **M04 只处理文档与文档/片段之间的关系**，**绝不**处理设备数据、传感数据、备件、工单等非文档实体。
- M03 负责「检索片段」，M04 负责「沿关系找到相关片段」；两者能力互补、不重叠。M06/M07 在需要关系推理时调用 M04，在需要直接召回时调用 M03。
- 关联图节点必须可回溯到 M03 中的真实片段（外键约束），不得出现悬空节点。

**验收要点**：人工删除一条边后，关联检索结果中该关系消失；自动/人工来源可区分。

### M05 设备数据管理

**目标**：管理设备运行数据，支持导入与模拟两种来源，并完成清洗与异常提取。

| 编号 | 名称 | 优先级 | 说明 |
|------|------|--------|------|
| REQ-M05-01 | 数据导入 | P0 | 导入设备运行表格数据，识别指标、时间范围、记录数；提供摘要与原始数据预览。 |
| REQ-M05-02 | 故障模拟 | P0 | **基于 M02 的设备配置**（设备类型、指标、阈值）选择场景（正常、主轴过热、轴承磨损、电压不稳等），一键生成并保存模拟数据。 |
| REQ-M05-03 | 数据清洗 | P0 | 支持缺失补全、偶发噪点处理、平滑规则；生成清洗后数据；同屏展示处理前后曲线。 |
| REQ-M05-04 | 异常提取 | P0 | **依据 M02 的告警规则**识别超限、持续升降、异常波动，输出结构化指标清单与异常摘要。 |
| REQ-M05-05 | 数据管理 | P0 | 数据集列表、查看、删除、按设备与时间范围筛选。 |

**边界**：M05 产出的「异常清单」是 M07 的输入；M05 判定异常**只依据 M02 阈值**，不自行定义标准。模拟数据必须与所选真实设备配置的指标集一致（指标名、单位、量级由 M02 决定）。

**验收要点**：同一份数据，修改 M02 阈值后重新提取，异常结果随之变化。

### M06 智能问答（单 Agent）

**目标**：提供面向用户的通用智能问答，融合 RAG 与 GraphRAG。

| 编号 | 名称 | 优先级 | 说明 |
|------|------|--------|------|
| REQ-M06-01 | 对话问答 | P0 | 用户以自然语言提问，Agent 给出回答；支持多轮上下文。 |
| REQ-M06-02 | 双知识源检索 | P0 | 回答前检索 M03 片段，并按需经 M04 做关系扩展，形成证据集。 |
| REQ-M06-03 | 引用溯源 | P0 | 回答标注来源文档名称、章节、片段，支持点击查看原文。 |
| REQ-M06-04 | 知识不足兜底 | P0 | 证据不足时明确提示「现有知识库未覆盖该问题」，**不得编造**。 |
| REQ-M06-05 | 会话管理 | P1 | 历史会话列表、重命名、删除。 |
| REQ-M06-06 | 范围限定 | P0 | 问答仅基于授权知识库（受 M01 数据范围权限约束）。 |

**边界**：M06 是**轻量通用问答**，不做设备数据的定量诊断、不产出工单；涉及具体设备故障诊断时，引导用户进入 M07 协同诊断。M06 与 M07 **共享同一知识底座（M03+M04）**，避免两套知识。

**验收要点**：回答均可溯源；无依据时不编造。

### M07 多 Agent 协同诊断

**目标**：以多个**分领域、有边界**的 Agent 协同完成设备故障诊断，输出可解释、可溯源的结论。

#### 7.1 Agent 领域划分与边界（核心）

| Agent | 领域 | 输入契约 | 输出契约 | 可用知识/工具 | 明确禁止 |
|-------|------|----------|----------|----------------|----------|
| 监测 Agent | 异常确认与分级 | M05 异常清单、M02 阈值 | 确认异常、严重度分级 | 设备配置（只读）、告警规则 | 不得推断根因、不得推荐备件 |
| 根因诊断 Agent | 故障根因分析 | 确认异常 + 证据 | 候选根因（按可能性排序）+引用 | M03、M04 | 不得推荐备件、不得给出安全操作 |
| 备件成本 Agent | 备件与成本 | 根因结论 | 备件清单、库存、停机损失 | M02 备件/停机损失 | 不得判断根因、不得给安全要求 |
| 安全规范 Agent | 安全与合规 | 拟定的维修方案/根因 | 安全要求、合规核查结论 | M03（安全规程）+M04 | 不得判断根因、不得推荐备件 |
| 工单 Agent | 工单编排 | 上述各 Agent 结论 | 结构化维修工单 | M02、诊断结果 | 不得新增未经上游确认的结论 |

**边界规则（强制）**：
1. **输入/输出契约化**：每个 Agent 的输出须符合预定义 schema，编排器做校验，越界字段一律拒绝。
2. **领域隔离**：Agent 只能访问其授权范围内的知识库与工具；根因 Agent 看不到备件库存，备件 Agent 看不到原始传感数据。
3. **安全优先/否决权**：安全规范 Agent 对涉及拆解、电气、参数调整的步骤拥有**否决权**——未通过安全核查的步骤不得进入工单。
4. **结论一致性**：多 Agent 结论冲突时，以**可核对的引用证据**为准；无证据的结论不得采纳。
5. **不越权生成**：任何 Agent 不得输出超出其职责的操作指令（如无依据的拆解指令）。

## 5. 验收标准

验收以 **P0 功能**与**共同要求**（本章 5.1）为基础；P1 功能纳入当期交付后单独验收，未交付不影响 P0 验收。

### 5.2 验收项

## 6. 自洽性校验与合理性复核

> 本节对全文进行交叉核对，确认整改方向已落地且模块间不矛盾。

### 6.1 六项整改落地核对

| 整改方向 | 落地位置 | 是否落地 |
|----------|----------|----------|
| ① 双端 | 1.2、M01、M10 | ✅ 用户端/管理端定义清晰，权限矩阵唯一权威 |
| ② 真实设备配置 | M02 | ✅ 台账+类型+指标+阈值+备件+停机损失，作为主数据 |
| ③ RAG 知识库管理 | M03 | ✅ 上传→分段→向量化→索引→检索→重排闭环 |
| ④ GraphRAG（LangGraph，仅文档关联） | M04 | ✅ 明确「只做文档间关联」，可管理可修改，与 RAG 职责分离 |
| ⑤ 单 Agent 问答 | M06 | ✅ 双知识源、引用溯源、知识不足兜底 |
| ⑥ 多 Agent 协同与边界 | M07 | ✅ 5 类 Agent + 契约化 + 领域隔离 + 安全否决 |

### 6.2 跨模块一致性检查

| 检查点 | 结论 | 依据 |
|--------|------|------|
| RAG 与 GraphRAG 是否职责重叠 | 不重叠 | M03=检索片段；M04=文档关系；边界条款明确 |
| GraphRAG 是否越界到设备数据 | 未越界 | M04 边界条款排除非文档实体；节点外键约束到 M03 片段 |
| 阈值/备件/停机损失是否单一来源 | 是 | 统一归 M02，M05/M07/M09 均引用，禁止硬编码 |
| 单 Agent 与多 Agent 是否两套知识 | 否，共享底座 | M06/M07 均基于 M03+M04；M06 遇具体故障引导至 M07 |
| 双端功能是否重叠冲突 | 无冲突 | 使用类归用户端、治理类归管理端；管理端仅可发起测试 |
| 权限是否覆盖所有模块 | 覆盖 | 1.6 依赖表均依赖 M01；M01 声明唯一权威矩阵 |
| 数据流是否有断点 | 无断点 | 1.5 主线：M02→M03/M04→M05→M07→M09，环环相扣 |
| 健康评分/风险提示是否有口径 | 已补 | REQ-M09-02 明确评分规则可配置 |
| 工单数据是否可能不一致 | 已约束 | REQ-M09-05 要求引用主数据，禁止二次录入 |

### 6.3 残留风险与提示

1. **多 Agent 推理非确定性**：验收以「关键结论命中 + 引用可核对 + 越界拦截 + 安全否决生效」为准，不要求逐字一致。
2. **GraphRAG 自动抽取质量**：P0 依赖人工管理兜底（REQ-M04-04），自动候选边审核为 P1。
3. **范围仍偏大**：P0 覆盖 10 个模块，建议按 1.5 主线分阶段演示，核心路径优先。
4. **安全否决的粒度**：需在实现时定义「涉及拆解/电气/参数调整」的判定清单。

### 6.4 合理性复核结论

- **合理性**：整改方向全部落地；模块划分按「能力」而非「页面」组织，减少耦合；主数据单一来源、知识双源分工、双端职责清晰，整体自洽。
- **相较 V1 的改进**：补齐权限、设备配置、量化非功能需求、健康评分口径、工单数据一致性、多 Agent 边界规则。
- **仍待完善**：LangGraph 关联图的抽取策略与安全否决清单需在详细设计中进一步细化。
