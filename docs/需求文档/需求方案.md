## 一、项目目标与使用场景

建设面向工业设备巡检与运维的 Web 系统，解决**告警难分析、维修知识难查找、诊断与工单脱节**的问题。系统应支持模拟数据演示，在无真实设备接入时完成从异常发现到维修工单导出的全过程。

**目标用户**

| 角色 | 职责 |
|------|------|
| 管理员 | 负责资料与数据治理 |
| 配置员 | 配置智能体并发布服务 |
| 维修工程师 | 核对故障依据、备件与维修步骤 |
| 生产管理人员 | 查看设备状态和停机风险 |
| 评审与体验用户 | 通过样例验证完整流程 |

## 二、业务流程与交付范围

**主流程：**

上传手册与导入或生成设备数据 → 文档分段建索引与传感数据清洗 → 配置协同诊断流程 → 测试并发布服务 → 查看设备状态与导出维修工单。

**交付范围说明**

- **P0**：首期必须交付的功能。
- **P1**：增强功能，纳入交付后按相应条目验收；未交付不影响 P0 验收。
- 首期应提供**可运行的预设协同流程**，可视化拖拽编排作为 P1。
- 知识索引构建属于 **P0**，片段人工校对属于 **P1**。

## 三、功能需求

### 3.1 数据与知识库管理

| 编号 | 名称 | 优先级 | 说明 |
|------|------|--------|------|
| REQ-01-01 | 知识库管理 | P0 | 支持创建多个知识库，按设备类型、厂商和故障等级分类，展示文档数量与更新状态。 |
| REQ-01-02 | 文档管理 | P0 | 支持维修手册、操作规程和历史维修记录的上传、预览、版本更新、启停和删除；停用文档不参与诊断检索。 |
| REQ-01-03 | 设备数据导入 | P0 | 支持导入设备运行表格数据，识别指标、时间范围和记录数，提供摘要与原始数据预览。 |
| REQ-01-04 | 故障模拟 | P0 | 支持选择设备类型及正常、主轴过热、轴承磨损、电压不稳等场景，一键生成并保存模拟运行数据。 |

### 3.2 数据处理

| 编号 | 名称 | 优先级 | 说明 |
|------|------|--------|------|
| REQ-02-01 | 文档分段 | P0 | 支持配置分段长度、重叠字数或按章节切分，预览片段内容、数量和字数。 |
| REQ-02-02 | 知识索引 | P0 | 将文档片段构建为可检索的知识索引，展示处理进度与就绪状态。片段文字编辑、关键词补充和分布展示属于 P1。 |
| REQ-02-03 | 数据清洗 | P0 | 支持勾选缺失补全、偶发噪点处理和平滑规则，生成清洗后数据，并同屏展示处理前后的曲线。 |
| REQ-02-04 | 异常提取 | P0 | 识别超限、持续升降和异常波动，输出结构化指标清单与易读的异常摘要，供后续诊断使用。 |

### 3.3 智能体构建

| 编号 | 名称 | 优先级 | 说明 |
|------|------|--------|------|
| REQ-03-01 | 角色配置 | P0 | 预设异常监测、根因诊断、工单调度三类角色，支持修改名称、职责、指令、分析参数和回复格式，并保存配置。 |
| REQ-03-02 | 知识与工具绑定 | P0 | 支持关联多个知识库、设置匹配严格度，并启用备件库存查询、停机损失计算和安全规范核查工具。 |
| REQ-03-03 | 可视化编排 | P1 | 支持拖拽角色节点、连接任务顺序、配置触发条件并保存流程，例如发现异常后继续诊断，正常时结束。 |

### 3.4 推理测试与服务部署

| 编号 | 名称 | 优先级 | 说明 |
|------|------|--------|------|
| REQ-04-01 | 诊断测试 | P0 | 支持选择故障数据或输入现象描述，运行协同诊断；分步展示各角色的执行状态、分析摘要、工具结果和最终结论。 |
| REQ-04-02 | 引用溯源 | P0 | 诊断结论应标明维修手册名称、章节及引用片段，支持点击查看原文，便于核对依据。 |
| REQ-04-03 | 服务发布 | P0 | 将测试通过的流程发布为可调用服务，生成访问地址与凭证，支持上线、暂停和版本切换。 |
| REQ-04-04 | 调用与监控 | P1 | 提供在线调用测试，展示累计调用次数、平均响应耗时、成功率和近期调用记录。 |

### 3.5 结果可视化与工单交付

| 编号 | 名称 | 优先级 | 说明 |
|------|------|--------|------|
| REQ-05-01 | 设备健康看板 | P0 | 展示设备健康评分、正常或预警或故障状态、关键指标趋势及未来故障风险提示，突出显示异常设备。 |
| REQ-05-02 | 故障溯源图 | P1 | 以关联图展示异常指标、异常模式、故障根因、引用条款与推荐备件之间的关系。 |
| REQ-05-03 | 维修工单 | P0 | 生成并预览标准维修作业工单，包含设备信息、故障根因、风险等级、备件及库存、安全要求、维修步骤与停机损失，支持下载为可打印或存档的文档。 |

## 四、业务数据要求

| 数据类别 | 主要内容 |
|----------|----------|
| 输入数据 | 维修手册、安全规程和历史案例；设备编号、采集时间、温度、振动、电流、转速；备件名称、型号、库存、采购单价及每小时停机损失标准。 |
| 过程数据 | 文档片段及来源章节页码、清洗后指标、异常摘要、角色执行记录、工具结果与知识引用。 |
| 输出数据 | 设备健康状态、诊断报告、风险提示及标准维修工单。 |

## 五、体验与可靠性要求

- **界面与反馈**：一级导航按五大模块组织。文档处理和诊断过程中应显示进度或阶段结果，操作失败时提供中文原因说明与处理建议。
- **演示准备**：预置至少 2 份完整维修手册样例和 3 种典型故障数据，支持通过电脑浏览器完成演示，无需连接真实工业设备。
- **诊断依据**：涉及设备拆解、电气操作和参数调整的维修步骤必须有知识库依据。知识不足时提示“现有知识库未覆盖该故障，请转交人工专家核查”，不得生成无依据的操作指令。
- **异常处理**：对文件格式错误、数据大量缺失和推理服务不可用等情况给出明确提示与后续操作指引，避免流程无响应或页面崩溃。

## 六、开发过程记录

使用华为云码道作为核心编程工具，保留真实使用日志、需求与提示词交互截图、代码生成及修改对比记录，以及搭建、联调和排错录屏。材料应与实际功能对应，并随作品整理提交。

## 七、验收标准

验收以 **P0 功能**和**共同要求**为基础。P1 功能纳入当期交付范围后单独验收；其未交付不影响 P0 验收。

| 验收项 | 通过条件 |
|--------|----------|
| 资料与样例 | 至少 2 份维修手册、3 种故障场景可用。能够上传、预览、更新和停用文档，停用内容不再被检索；导入或模拟数据可查看。 |
| 数据处理 | 能够预览文档分段并构建可检索索引；清洗前后曲线可对照，异常指标清单与摘要可用于诊断。 |
| 协同诊断 | 预设流程能够完成异常监测、根因诊断与工单调度；角色配置、知识库和工具绑定生效，阶段结果可查看。 |
| 结论与依据 | 预设故障的异常指标、诊断结果与样例预期一致；引用可打开核对，备件库存和停机损失与基础数据一致。知识不足时按要求转人工。 |
| 服务发布 | 发布后获得可调用地址与凭证，能够取得诊断结果；上线、暂停及版本切换状态与实际调用行为一致。 |
| 看板与工单 | 看板显示设备评分、状态、指标趋势和风险提示；导出工单可打开，且内容与诊断结果及引用一致。 |
| 完整流程与异常 | 能够在系统内完成从数据准备到工单导出的流程；处理和诊断有进度反馈，错误文件、严重缺失数据及服务不可用时有明确提示。 |
| 过程记录 | 日志、交互截图、代码修改记录与录屏齐全，内容真实，并能对应已实现功能。 |

**增强功能验收**

知识片段修改后可重新构建索引；可视化编排能够保存并按条件运行；调用监控与实际调用记录一致；故障溯源图与诊断证据一致。上述要求分别对应 REQ-02-02 的 P1 部分、REQ-03-03、REQ-04-04 和 REQ-05-02。
