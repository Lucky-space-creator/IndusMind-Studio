# 开发智能体定义（五个）

> 本项目采用「AI 模块用 Python 服务、Java 只做传统业务后端」的分工。据此凝练五个开发智能体，用于后续分工协作。
> 智能体定义文件：`.codeartsdoer/agents/`

## 一、总体分工

| 智能体 | 定义文件 | 负责 | 不负责 |
|--------|----------|------|--------|
| 项目架构智能体 | `project-architect.md` | **开发总统筹**：需求→架构映射、模块与边界治理、契约、技术选型、计划编排与派发、质量门禁、自洽性复核 | 不写业务实现、不改需求 |
| Java 开发智能体 | `java-developer.md` | Java 多模块传统后端（业务/权限/配置/数据/工单/发布/审计） | 不实现 RAG/Agent；不改前端 |
| Python 开发智能体 | `python-developer.md` | 独立 AI 服务：RAG、GraphRAG、单 Agent、多 Agent(LangGraph) | 不写 Java；不碰业务库；不改前端 |
| 前端开发智能体 | `frontend-developer.md` | 双端前端（用户端 + 管理端） | 不写 Java/Python；不改架构 |
| 数据层智能体 | `data-layer.md` | 数据库 schema、**表职责划分**、DDL/索引/约束、数据字典、迁移与一致性、主数据治理 | 不写业务逻辑/Mapper/Service；不设计向量/图库 |

## 二、各智能体职责要点

### 1. 项目架构智能体（开发总统筹）
- **统筹开发**：需求↔架构映射、任务拆解与派发（业务→Java、AI→Python、界面→前端）、计划编排与里程碑、进度跟踪与阻塞处理。
- **模块与边界治理**：按功能分包；守护依赖单向无环（应用→领域→基础；领域内 D0→D1→D2→D3）与主数据单一来源。
- **契约管理**：跨模块 Facade+DTO/领域事件、**Java ↔ Python 接口契约**（`/rag/*`、`/graph/*`、`/chat`、`/diagnosis/run`）、前端 API 约定；契约变更先更新架构文档再同步三方。
- **技术选型与依赖治理**：栈统一（Maven/Spring Boot 3.x/JDK21/MyBatis-Plus/MySQL/Redis；Python FastAPI/LangChain/LangGraph），新依赖须评审并获用户确认。
- **质量门禁与复核**：定义 DoR/DoD，评审三方交付是否越界/一致；每次架构变更后做**自洽性复核**。
- **决策权限**：模块/包结构/依赖/契约/派发顺序可自主决定；需求范围、新依赖、六大整改方向、破坏性契约变更须与用户确认。
- **边界**：不写业务实现、不改需求、不绕过质量门禁、不确定即停。

### 2. Java 开发智能体
- 按功能分包：功能包（=模块）下含 controller/service/mapper/model/api…；只经 Facade+DTO 跨模块。
- 主数据单一来源：阈值/备件/停机损失仅取自 `hwc-device`。
- 构造器注入、**注解优先**（Bean/事务/校验/配置绑定用注解 + Lombok）、配置外置、统一返回体与异常、SLF4J 日志。
- **复杂 SQL 写 XML Mapper**（join/子查询/动态条件/聚合/批量），不在 Mapper 接口堆注解、不在 Service 拼 SQL；参数用 `#{}`；简单单表 CRUD 用 MyBatis-Plus。
- 注释粒度适中：类注用途、公共方法注 `@param`/`@return`/`@throws`、复杂逻辑注"为什么"。
- **AI 能力一律经 `hwc-ai-client` 调用 Python 服务**。

### 3. Python 开发智能体
- 实现 RAG（`/rag/*`）、GraphRAG（`/graph/*`）、单 Agent（`/chat`）、多 Agent（`/diagnosis/run`）。
- 多 Agent 领域边界：监测/根因诊断/备件成本/安全规范/工单——**契约化、领域隔离、安全否决、引用为准**。
- RAG 只答「片段相关」，GraphRAG **只做文档间关联**；知识不足不编造。
- 持有向量库与图库（Neo4j）；业务元数据以 Java 为准。

### 4. 前端开发智能体
- 用户端：看板/问答/诊断/工单，**无管理入口**；管理端：设备配置/知识库/文档关联/数据/Agent与流程/发布监控/账号权限/审计。
- 遵循 UI/UX 优先级规范与反 AI 设计；组件复用优先；进度反馈与中文错误提示；引用溯源。

### 5. 数据层智能体
- **表职责设计**：按领域归属表（`sys_/dev_/kb_/data_/agent_/pub_/wo_`），一表一职责，主数据与业务/过程数据分离。
- **规范**：小写下划线命名、表名单数；通用字段 `id/create_time/update_time/creator/updater/deleted/version`；主键 BIGINT；逻辑删除 + 乐观锁。
- **索引与约束**：主键 + 业务唯一键 + 高频查询列索引；默认物理外键不建（应用层保证）。
- **主数据治理**：`dev_*`（设备/阈值/备件/停机损失）唯一权威，变更须评审并评估下游影响。
- **交付物**：DDL、版本化迁移脚本、数据字典、**表职责矩阵**（见 `docs/设计文档/数据模型设计.md`）。
- **边界**：不写业务逻辑与 Mapper/Service；向量库/图库归 Python。

## 三、协作与交接

```
                       ┌───────────────────────────────┐
                       │        项目架构智能体          │  ← 开发总统筹
                       │  需求→架构 · 边界 · 契约 · 编排 │
                       └───────────────┬───────────────┘
        契约/边界/DoR/DoD 派发 ┌────────┴───────────┬──────────────┬──────────────┐
                                ▼                    ▼              ▼              ▼
                        数据层智能体          Java 开发智能体  Python 开发智能体  前端开发智能体
                                │                    │
                                └── 表/DDL → 实体/Mapper ──┘  （Java↔Python 经 hwc-ai-client 按契约通信）
                                        交付回评审 → 自洽性复核
```

- **派发**：架构智能体按契约与 DoR 派发；四方按 DoD 交付。
- **数据先行**：数据层先定表与 DDL，Java 智能体据此实现实体/Mapper/XML。
- **评审**：架构智能体校验交付的边界/契约/一致性，未达 DoD 不放行。
- **变更**：契约变更先更新 `docs/设计文档/Java多模块架构设计.md` 再同步四方；冲突以需求文档与架构文档为准。
