# 项目开发规则

本文件定义本项目的目录组织约定与协作规则，所有开发、测试与文档工作均须遵循。

## 一、顶层目录职责

| 目录 | 职责 | 说明 |
|------|------|------|
| `docs/` | 开发与测试文档 | 内部按文档功能分类为子目录，禁止在根下平铺散落文档 |
| `test/` | 测试用例构建与测试结果 | 最后阶段的测试用例落盘与测试结果归档 |
| `code/` | 前后端代码 | 前端与后端源码统一存放于此，不散落在仓库根目录 |

## 二、docs/ 子目录分类

`docs/` 按文档功能划分子目录：

```
docs/
├── 需求文档/     # 需求说明、PRD、需求变更
├── 设计文档/     # 架构设计、模块设计、UI/UX 设计
├── 开发规范/     # 编码规范、目录规则、skill 提取（本文件所在目录）
├── 接口文档/     # API 定义、数据模型、联调说明
└── 测试文档/     # 测试方案、测试报告、用例说明
```

规则：
- 新增文档时先判断功能归属，放入对应子目录。
- 子目录按需扩展，命名保持中文语义一致。
- 每份文档结尾注明来源与更新时间。

## 三、test/ 目录约定

```
test/
├── 测试用例/     # 测试用例源码/描述（最终测试阶段构建）
└── 测试结果/     # 测试执行产物：日志、报告、覆盖率、截图
```

规则：
- 测试用例在功能实现完成后、交付前统一构建，位于 `test/测试用例/`。
- 所有测试执行结果（含失败）归档到 `test/测试结果/`，不得只保留通过项。
- 测试须覆盖正常路径与边界情况。

## 四、code/ 目录约定

```
code/
├── backend/      # 后端代码
└── frontend/     # 前端代码
```

规则：
- 前后端代码分仓分目录存放，禁止交叉混放。
- 具体技术栈按项目实际情况落地，规范见 `docs/开发规范/后端开发skill提取.md` 与 `前端开发skill提取.md`。
- 不修改项目基础配置与目录结构，除非任务明确要求。
