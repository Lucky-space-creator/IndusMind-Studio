# 数据模型设计（表职责设计）

> 出品：数据层智能体
> 版本：V1.0
> 关联：总纲 `docs/设计文档/系统总体架构设计.md`；后端 `docs/设计文档/Java后端详细设计.md` §5；模块 `docs/设计文档/Java多模块架构设计.md`
> 定位：**业务关系库（MySQL 8）** 的表职责设计、命名与字段规范、索引约束、主数据治理与迁移。
> 不含：向量库（pgvector）与图库（Neo4j）—— 归 Python 服务。

---

## 1. 设计原则

- **按领域归属表**：表前缀体现领域，与 15 个工程模块对应。
- **一表一职责**：不把多职责塞进宽表；配置数据、业务数据、过程数据、日志数据分离。
- **主数据唯一**：设备/指标/阈值/备件/停机损失为全系统唯一权威，跨领域只存引用 id。
- **引用而非复制**：跨库（向量/图）由 Python 侧维护，业务侧只存元数据与关系定义。
- **可追溯**：关键表含审计字段，关键操作可回溯。

---

## 2. 命名与通用字段规范

| 项 | 规范 |
|----|------|
| 表名/字段名 | 小写 + 下划线；表名单数（`dev_info`、`kb_document`） |
| 主键 | `id` BIGINT（全库统一，雪花/自增） |
| 通用字段 | `create_time`、`update_time`、`creator`、`updater`、`deleted`(逻辑删除)、`version`(乐观锁) |
| 布尔 | `is_xxx`(tinyint) |
| 时间/金额 | `datetime` / `decimal(p,s)` |
| 索引命名 | 普通 `idx_<表>_<列>`；唯一 `uk_<表>_<列>` |
| 外键 | **默认物理外键不建**，应用层保证引用完整性 |

## 3. 表职责矩阵（按领域）

### 3.1 权限与审计（`hwc-security`）
| 表 | 职责 | 类型 | 主要访问方 |
|----|------|------|-----------|
| `sys_user` | 账号（加盐哈希、状态） | 配置 | security |
| `sys_role` | 角色（含可访问端 user/admin/both） | 配置 | security |
| `sys_user_role` | 用户-角色关联 | 关联 | security |
| `sys_permission` | 权限（code/module/action） | 配置 | security、前端（登录返回） |
| `sys_role_permission` | 角色-权限关联 | 关联 | security |
| `sys_role_data_scope` | 角色数据范围 | 配置 | security |
| `sys_audit_log` | 操作审计 | 日志 | security |

### 3.2 设备配置（`hwc-device`）—— **主数据**
| 表 | 职责 | 类型 | 主要访问方 |
|----|------|------|-----------|
| `dev_type` | 设备类型（名称、厂商） | 主数据 | device、device-data、workorder |
| `dev_model` | 型号规格（引用 type） | 主数据 | device、workorder |
| `dev_info` | 设备台账 | 主数据 | device、device-data、workorder、agent |
| `dev_metric` | 监测指标定义（单位、频率） | 主数据 | device、device-data、agent |
| `dev_metric_threshold` | 指标阈值（正常/预警/故障） | 主数据 | device-data（异常判定）、agent |
| `dev_alarm_rule` | 告警规则（等级、触发） | 主数据 | device-data、agent |
| `dev_spare_part` | 备件（库存、单价、安全库存） | 主数据 | agent（备件成本）、workorder |
| `dev_downtime_cost` | 停机损失标准 | 主数据 | agent（成本）、workorder |

### 3.3 知识库（`hwc-knowledge`）
| 表 | 职责 | 类型 | 主要访问方 |
|----|------|------|-----------|
| `kb_knowledge_base` | 知识库（分类） | 配置 | knowledge、docgraph、agent |
| `kb_document` | 文档（版本、启停、文件地址） | 业务 | knowledge |
| `kb_segment` | 片段（内容、来源章节页、字数） | 业务 | knowledge、docgraph、agent |
| `kb_index_task` | 索引任务（状态、进度、版本） | 过程 | knowledge |

### 3.4 文档关联（`hwc-docgraph`）—— GraphRAG 业务元数据
| 表 | 职责 | 类型 | 主要访问方 |
|----|------|------|-----------|
| `kb_graph_node` | 关联图节点（doc/section/segment，ref→片段） | 业务 | docgraph |
| `kb_graph_edge` | 关联边（关系类型、来源 auto/manual） | 业务 | docgraph、workorder（溯源） |

> 只描述**文档/片段间**关系，节点外键回溯 `kb_segment`；图的实际存储（Neo4j）由 Python 持有，此处仅存元数据可重建。

### 3.5 设备数据（`hwc-device-data`）
| 表 | 职责 | 类型 | 主要访问方 |
|----|------|------|-----------|
| `data_dataset` | 数据集（来源导入/模拟、时间范围、记录数） | 业务 | device-data、workorder |
| `data_record` | 原始记录（采集时间、指标值） | 业务 | device-data |
| `data_cleaned` | 清洗后数据（规则、结果） | 过程 | device-data、workorder |
| `data_anomaly` | 异常清单（类型、摘要） | 过程 | device-data → agent |

> `data_record` 指标存储形态（JSON vs 宽表）为待细化项，按数据集规模在 `hwc-device-data` 内定，遵循大表分区/归档策略。

### 3.6 Agent 与诊断（`hwc-agent`）
| 表 | 职责 | 类型 | 主要访问方 |
|----|------|------|-----------|
| `agent_definition` | Agent 配置（职责/指令/参数/格式） | 配置 | agent |
| `agent_tool_binding` | 知识/工具绑定（范围、严格度、工具） | 配置 | agent |
| `agent_flow` | 协同流程（版本、状态） | 配置 | agent、publish |
| `agent_flow_node` | 流程节点（Agent、顺序、触发条件） | 配置 | agent |
| `agent_run` | 运行记录（单/多、输入、状态、结论） | 过程 | agent、workorder |
| `agent_step` | 步骤明细（阶段、摘要、工具结果、引用、耗时） | 过程 | agent、workorder |
| `diagnosis_record` | 诊断记录（设备、结论、引用、风险） | 业务 | agent、workorder、publish |
| `chat_session` / `chat_message` | 问答会话与消息（含引用） | 业务 | agent |

|----|------|------|-----------|

| `pub_version` | 版本记录 | 业务 | publish |
| `pub_call_log` | 调用日志（traceId、耗时、成功） | 日志 | publish |

### 3.8 看板与工单（`hwc-workorder`）
| 表 | 职责 | 类型 | 主要访问方 |
|----|------|------|-----------|
| `wo_dashboard_metric` | 看板快照（评分、状态、风险） | 过程 | workorder |

## 4. 主数据治理

- `dev_*` 为唯一权威；其变更须评审并评估对**数据异常提取、诊断、工单**的影响。
- 阈值/备件/停机损失变更留痕；下游自动引用最新值，**禁止**在业务表冗余存储快照（如需历史，另建版本表）。
- 主数据表变更由数据层智能体执行，影响分析由项目架构智能体统筹。

---

## 5. 索引与约束

- 每表主键；业务唯一键建唯一约束（如 `uk_dev_info_code`）。
- 外键列、状态/时间过滤列、排序列建普通索引。
- 大表（`data_record`）按 `dataset_id`/时间建索引，必要时分区或归档。
- 避免冗余索引与 `SELECT *`。

---

## 6. 数据迁移与版本

- 脚本版本化 `V{序号}__{描述}.sql`，可前进/可回滚。
- 结构变更同步更新**数据字典**与本文表职责矩阵。
- 破坏性变更先与项目架构智能体确认。

---

## 7. 与模块/实体映射

- 表 ↔ 实体：由 Java 开发智能体按本设计实现 `model/entity`；Mapper/XML 遵守其持久层规范（复杂 SQL 写 XML）。
- 复杂 SQL：本设计提供表关系与索引依据，SQL 由 Java 智能体实现。
- 跨库边界：MySQL 业务表 ↔ pgvector/Neo4j，以 Java 元数据为准，Python 侧可重建。
