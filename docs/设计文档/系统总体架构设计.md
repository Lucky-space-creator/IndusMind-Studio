## 1. 设计目标与约束

### 1.1 目标
构建面向**工业设备巡检与运维**的智能系统，打通「知识沉淀 → 智能问答 → 多 Agent 协同诊断 → 工单交付」主线，支持在无真实设备接入时用模拟数据完成端到端演示。

### 1.2 硬约束（不可弱化）
1. **双端**：用户端 + 管理端，共用后端。
2. **真实设备配置**：设备/指标/阈值/备件/停机损失为全系统主数据。
3. **RAG 知识库管理**：负责片段级检索。
4. **GraphRAG 文档关联**：LangGraph 构建可管理可修改的文档关系，**只做文档间关联**。
5. **单 Agent 问答**。
6. **多 Agent 协同**：分领域、有边界。
7. **技术分工**：Java 只做传统业务后端；RAG / GraphRAG / Agent 全部由独立 Python 服务提供，Java 经 `hwc-ai-client` 以 HTTP 调用。
8. **优先级**：P0 构成可演示闭环。

## 2. 总体架构

系统由四个可独立部署的部分组成：**前端双端**、**Java 业务后端（多模块，两个启动应用）**、**Python AI 服务**、**存储与中间件**。

```
┌──────────────┐   ┌──────────────┐
│  用户端 Web   │   │  管理端 Web   │        ← 前端（静态资源）
└──────┬───────┘   └──────┬───────┘
       │ /api/user/**      │ /api/admin/**
       ▼                   ▼
┌─────────────────────────────────────────────┐
│        Java 多模块后端（Spring Boot 3.x）      │
│  hwc-app-user (jar)      hwc-app-admin (jar)  │
│  ── 领域模块：device / knowledge / docgraph /  │
│     device-data / agent / publish / workorder │
│  ── 基础：security / infra / domain / common  │
│  ── 边界：hwc-ai-client（唯一 AI 出口）         │
└───────┬───────────────┬──────────────┬────────┘
        │               │              │
        ▼               ▼              ▼
  ┌──────────┐   ┌───────────┐   ┌──────────────┐
  │  MySQL   │   │  Redis    │   │ 对象存储/MinIO│
  └──────────┘   └───────────┘   └──────────────┘
        ▲
        │ HTTP（/rag/* /graph/* /chat /diagnosis/run）
        ▼
┌─────────────────────────────────────────────┐
│        Python AI 服务（FastAPI）              │
│  RAG · GraphRAG(LangGraph) · 单 Agent ·       │
│  多 Agent 协同（LangGraph 编排）              │
└───────┬───────────────┬──────────────────────┘
        ▼               ▼
  ┌──────────┐   ┌──────────┐
  │ 向量库    │   │ Neo4j    │
  └──────────┘   └──────────┘
```

**关键边界**：Java 持业务元数据；Python 服务持向量索引与关系图；两者仅经 `hwc-ai-client` 通信。

## 3. 技术栈选型

### 3.1 前端
| 方面 | 选型 | 理由 |
|------|------|------|
| 框架 | **React 18 + TypeScript** | 与前端 skill 生态（react-bits 动态组件、shadcn/ui）直接复用；类型安全 |
| 构建 | Vite | 启动快、生态成熟 |
| 路由 | React Router v6 | 双端独立路由 |
| 状态 | Zustand（轻量） + TanStack Query（服务端状态/缓存） | 减少样板、贴合请求缓存 |
| UI 库 | 用户端：shadcn/ui + Tailwind；管理端：Ant Design 5 | 用户端重设计感/反 AI 味；管理端重表格表单效率 |
| 动效 | framer-motion / react-bits | 复用组件库动效 |
| 图表 | ECharts | 看板指标趋势、清洗前后曲线 |
| 请求 | Axios 封装 + 统一拦截（鉴权/错误） | 中文错误提示、Token 注入 |
| 工程 | pnpm workspace 单仓多包 | 双端共享 types/api/ui |

> 备选：Vue 3 + Element Plus（若团队更熟 Vue）。**默认采用 React 方案**，如需切换请告知项目架构智能体。

### 3.2 后端（Java）
| 方面 | 选型 |
|------|------|
| 语言/运行时 | Java 21（虚拟线程） |
| 框架 | Spring Boot 3.x、Spring Web、Spring Security、Spring Validation |
| 构建 | Maven 多模块 |
| 持久化 | MyBatis-Plus + MySQL 8；Redis（会话/缓存） |
| 接口文档 | SpringDoc OpenAPI |
| 工具 | Lombok、Hutool；日志 SLF4J + Logback |

### 3.3 AI 服务（Python）
| 方面 | 选型 |
|------|------|
| 语言 | Python 3.10+ |
| Web | FastAPI + Uvicorn |
| 编排/链路 | LangChain、**LangGraph**（文档关联与多 Agent 编排） |
| 向量库 | pgvector（默认，复用 PostgreSQL）/ Milvus / Qdrant |
| 图库 | **Neo4j**（GraphRAG 关联图） |
| 模型接入 | LLM + Embedding + Reranker（可配置 provider） |

### 3.4 存储与中间件
| 组件 | 用途 | 归属 |
|------|------|------|
| MySQL 8 | 业务元数据（设备/文档/诊断/工单/权限） | Java |
| Redis | 会话、缓存、限流 | Java |
| 对象存储（MinIO） | 文档原文文件 | Java |
| 向量库 | 片段向量索引 | Python |
| Neo4j | 文档关联图 | Python |

### 3.5 部署与运维
- 前端：`admin-web`、`user-web` 构建为静态资源，Nginx 托管。
- 后端：`hwc-app-user.jar`、`hwc-app-admin.jar` 独立启动（可同一 JVM 或分端口）。
- AI 服务：Uvicorn/Gunicorn 承载，独立部署。
- 可选：Nginx/网关统一入口，按 `/api/user`、`/api/admin` 路由；AI 服务仅内网可达。

## 4. 前端项目架构与模块划分

### 4.1 工程结构（pnpm workspace 单仓多包）
```
frontend/
├── apps/
│   ├── user-web/          # 用户端
│   └── admin-web/         # 管理端
├── packages/
│   ├── shared-types/      # 接口类型、枚举
│   ├── shared-api/        # Axios 封装、API 客户端、鉴权
│   └── shared-ui/         # 通用组件、图表、动效封装

```

单应用内目录（按功能分包，与后端一致）：
```

├── components/            # 跨功能通用组件
├── api/                   # 接口调用
├── store/                 # 状态
├── router/                # 路由

```

### 4.2 前端功能模块划分
| 端 | 功能模块 | 对应需求 |
|----|----------|----------|
| 用户端 | 设备健康看板、智能问答、协同诊断、故障溯源图、维修工单 | M06、M07、M09 |
| 管理端 | 设备配置、知识库、文档关联、数据管理、Agent与流程、发布监控、账号权限、审计 | M02–M05、M08、M01、M10 |

- **用户端不含任何配置/治理/发布入口**；管理端不承担面向维修工程师的日常诊断操作（可发起测试）。

## 5. 后端项目架构与模块划分（Java 多模块）

> 详细设计见 `docs/设计文档/Java多模块架构设计.md`；本节为总览。

**分层（15 模块，按功能分包：功能包下含 controller/service 等）**
- 基础层：`hwc-common`、`hwc-common-web`、`hwc-security`
- 模型层：`hwc-domain`
- 基础设施层：`hwc-infra`、`hwc-ai-client`
- 领域层：`hwc-device`、`hwc-knowledge`、`hwc-docgraph`、`hwc-device-data`、`hwc-agent`、`hwc-publish`、`hwc-workorder`
- 应用层：`hwc-app-user`、`hwc-app-admin`

**依赖规则**：应用→领域→基础**单向无环**；领域内 D0(device/knowledge)→D1(device-data/docgraph)→D2(agent)→D3(workorder/publish)；主数据仅 `hwc-device` 权威；AI 能力仅经 `hwc-ai-client`。

## 6. AI 服务架构与模块划分（Python）

### 6.1 工程结构
```
ai-service/
├── app/
│   ├── api/               # 路由：rag.py / graph.py / chat.py / diagnosis.py
│   ├── rag/               # 分段、向量化、索引、检索、重排
│   ├── graphrag/          # 关系抽取、关联图管理、关联检索（LangGraph）
│   ├── agents/
│   │   ├── single/        # 单 Agent 问答
│   │   └── multi/         # 多 Agent：nodes(监测/根因/备件成本/安全/工单) + graph(编排)
│   ├── core/              # LLM/Embedding/Reranker 接入、配置、schema 校验
│   └── models/            # 请求/响应 DTO
└── pyproject.toml
```

### 6.2 模块职责
| 模块 | 职责 | 对外接口 |
|------|------|----------|
| RAG | 片段索引与检索 | `POST /rag/index`、`/rag/reindex`、`/rag/search`、`/rag/document-status`、`/rag/delete` |
| GraphRAG | 文档关系抽取与关联检索（只做文档间关联） | `POST /graph/extract`、`/graph/query`、`/graph/sync` |
| 单 Agent | 通用问答（RAG+GraphRAG 双源、引用、兜底） | `POST /chat` |
| 多 Agent | 协同诊断（LangGraph 编排、领域边界、安全否决） | `POST /diagnosis/run` |

> 同步类接口（document-status/delete/sync）用于文档生命周期变更时同步向量库与图（见需求分析报告 A2）。

## 9. 关键决策与风险（项目架构智能体）

### 9.1 关键决策
| 决策 | 结论 | 理由 |
|------|------|------|
| AI 落地 | Python 服务 + Java 传统后端 | 保留 LangGraph 生态；职责清晰 |
| 前端框架 | **React 18 + TS**（已确认） | 复用前端 skill（react-bits/shadcn） |
| 双端形态 | 单仓多包，两应用共用后端 | 代码复用 + 严格隔离 |
| 向量库 | **pgvector**（已确认，可换 Milvus/Qdrant） | 复用 PostgreSQL，降低部署复杂度 |
| 图库 | Neo4j | GraphRAG 成熟选型 |

### 9.2 风险与缓解
| 风险 | 缓解 |
|------|------|
| AI 服务不可用 | `hwc-ai-client` 熔断降级 + 中文提示，不阻塞其余功能 |
| 多 Agent 非确定性 | 验收以「结论命中 + 引用可核 + 越界拦截 + 安全否决生效」为准 |
| 范围偏大 | 按 1.5 主线分阶段演示，P0 核心路径优先 |
| 前后端契约漂移 | 契约由项目架构智能体统一维护，变更先改文档再同步三方 |

### 9.3 已确认决策
1. 前端框架：**React 18 + TS**（用户端 shadcn/ui + Tailwind，管理端 Ant Design 5）。
2. 向量库：**pgvector**（复用 PostgreSQL）。
3. 统一入口：默认由 **Nginx** 承担（如需独立网关，后续设计再定）。
